# Configuration guide

| File | Use |
|---|---|
| `imba_chess_v4.toml` | Base architecture/data config and the ckpt34 SF2400 evaluation protocol. Default `--config` for training, Stockfish/model-pair evaluation and corpus scripts. |
| `imba_chess_v4_laptop.toml` | Laptop supervised continuation from flattened ckpt34 at its saved learning rate, in a separate checkpoint directory. |
| `imba_chess_v4_aux3.toml` | v4 plus three auxiliary WDL heads; base for stage-2 runs with auxiliary value learning. |
| `eval_flatten_sf2400.toml` | Frozen SF2400 halving recipe for flattened checkpoints (ckpt34 r4/b2048 confirmation, seed 1042). |
| `self_play.toml` | **Recommended stage-2 recipe and the default of `run_self_play.py`** (see README "Recommended stage-2 run"): plain Gumbel 256 with raw Q at value scale 0.5, bf16 collection, fast 64-simulation play-out of decided games, in-flight games carried across phases, 160 slots (5 workers x 32 on a 16 GB GPU), 500k replay trained once per position, constant LR 2e-4 with EMA 0.995, policy surprise, 3-horizon auxiliary value (0.15). Same settings as `self_play_s256_bf16_lr2e4_carry.toml`, whose header holds the lineage's history. |
| `self_play_s256_bf16*.toml` | Configs of the 2026-10 5070 Ti lineage, kept so those runs resume under their recorded identity. |
| `self_play_5090.toml` | 32 GB recipe of the tactical fork of the vmix run: 256 slots, tactical Gumbel 512 (root forcing, forcing floor, minimax weight 0.5), 1M-position replay, LR 2e-4 with 4-step accumulation, 0.25 search-WDL value mix, 3-horizon auxiliary value (0.15), regret restarts. |

Every stage-2 run streams its starting positions from the training corpus through `[streaming]`. The seed manifest passed with `--seeds` supplies only the held-out monitor openings used by strength screens.

A model checkpoint needs compatible architecture, input encoding, vocabulary and head shapes; only flattened checkpoints load. Stage-2 resume verifies a SHA-256 of every setting plus the base-config bytes, so any edit to either, including a comment, is a new run identity. Paired evaluation progress is keyed on the same identity. Runs and in-progress evaluations created before 2026-09-29 cannot be resumed by current code; runs launched from a source snapshot resume with that snapshot.

Execution controls can change without replacing training state: CUDA inference uses FP32 with TF32 disabled, and decoder choices follow the algorithm internally. `run_self_play.py --concurrent-games` overrides collection slots without altering search targets or the stored config identity, and records the override in run metrics. Evaluation concurrency remains controlled by its config. None of these change training token batch size, LR, reuse or collection thresholds; changing learning settings is a separate experiment.

Gumbel stage-2 training compiles the CUDA model forward and loss by default, with mask construction outside the graph. The shared model and checkpoint keys stay plain, and the compiled callable is reused across collect/train phases. The first training batch pays compilation or cache-loading costs; later calls can compile additional graphs for new shapes. Both `run_self_play.py` and `train_self_play.py` accept `--no-compile-training` for short runs or eager comparisons. This execution option does not change configuration identity or resume compatibility, and `run_self_play.py` records the effective choice as `training_compiled` in its `run_start` metrics. CPU training stays eager.

The shared CUDA search runtime also compiles the FP32 root model forward using dense SDPA by default, with dense-mask construction and ragged merge/split outside the graph. Its local wrapper shares the original model weights, so actor refreshes and plain checkpoints keep working. Runtime inference options record the executor's actual `root_compiled` status. BF16 roots stay eager because compilation exceeded root-logit parity tolerances in CUDA checks. Root compilation has its own first-call and shape-specialization costs, separate from training and decode compilation.

Gumbel searches reuse the previous move's played child as the next root instead of re-running the game history: that child was decoded as exactly the next root token against the same prefix, so its evaluation and K/V row become the next root and prefix (`inference_runtime._RootCarry`). The full root forward still runs for a game's first move, after any weight refresh, for a different actor, or whenever the history does not match the carried child. Search tree decodes use one fused Triton attention kernel per layer (`model/decode_attention.py`) that reads each game's history and its ancestors straight from the K/V arena, applies SiLU to the fresh projections, and keeps attention scores in float32. Both changes alter numerics slightly; on real waves both measured closer to a float64 reference than the paths they replaced.

A collection phase's size is `[collection] fresh_positions` (training positions) or, when set, `fresh_games` (completed training games; `config/self_play.toml` uses 640, 4x its 160 parallel games). Launching stops once the phase reaches it; with `carry_over_games` the in-flight games finish under the next actor. Training per position is set by `[learning] reuse`, so the phase size only regroups the same training into fewer, larger weight updates. Both sizes may change when resuming with `--previous-config`.

`run_self_play.py` saves on one cadence, `--save-every` iterations (default 5, about 12 minutes with 640-game phases): the full trainer state (model, optimizer, EMA, replay progress) as that iteration's actor; `scripts/extract_ema.py` writes its EMA weights out for evaluation. Between saves the weights stay in memory: the actor id is the hash of their in-RAM serialization, and collection workers receive them through `/dev/shm`. A screen saves the actor and EMA it evaluates (promotion makes that actor the best file), and graceful stops always leave a current full state. After a crash the run resumes from the last full state and redoes the training since; replay data and the start stream continue, the current best stays the screen anchor, and a pruned EMA file is rewritten from the restored EMA weights. Forking a run with `--initialize-optimizer` needs one of the full actors.

The collection worker startup/progress/shutdown timeout flags are also execution-only. Gameplay errors abort the collection phase; interrupted launches remain journaled for retry. Without regret restarts the start stream is journaled before each replay flush rather than at every launch, so a crash can reissue only starts whose games were lost unpublished. Replay shards are fsynced at every flush, while the manifest that indexes them is rewritten only at phase ends and garbage collection; a restart indexes any shards it lacks. Completed-phase counters recover from replay manifest summaries. Older manifests acquire those summaries in one pass through each surviving legacy shard, without changing trajectory data.

The shared inference runtime revision `shared-search-v2` preserves root capture/check/promotion flags and backs up pure negamax values before applying `minimax_weight` once per edge. Existing self-play weights and optimizer state can resume with these corrections; future games use the corrected search. An in-progress evaluation saved with the previous runtime revision requires a new output file or, for `run_stockfish_eval.py`, a new output directory. The batched SF runner checks both its manifest and each completed batch so old results cannot be mixed with the corrected search protocol.
