# Frozen actor 54 policy/value diagnostics

Completed results: [September 20 report](POLICY_REGRESSION_RESULTS_2026-09-20.md). All 500 games completed; historical transfer remains blocked by missing genuine replay.

The standalone `scripts.audit_search_improvement` CLI now also accepts
`policy-match`, `policy-positions`, `mixed-search`, and `transfer`. Their
implementation is in `scripts/audit_policy_regression.py`. No training, loss,
or production promotion code changes are involved.

The campaign is in `artifacts/eval/policy-regression-2026-09-20/`. `run.py`
runs one greedy pair, one pair per search arm, and one cached-position comparison
before the full evaluations. Pilots resume into the full 50-pair samples. Read
`status.json`, stage logs, and the incremental JSON files in `greedy/`, `mixed/`,
`positions/`, and `transfer/`. Checkpoints, configuration, seeds, source snapshots
and hashes are frozen per diagnostic output. Incompatible resumes fail; completed
games and administrative limits are preserved, while errors can be retried.

Each match uses 50 distinct monitor source games with color swaps. All search
uses 512 simulations, scale 0.1, top-m 16, depth 32, zero noise, FP32 and disabled
TF32. Greedy selects only the highest-probability legal move. Both checkpoints
receive identical full-history preprocessing.

Mixed search drives two ordinary search coroutines with the same composed
predictions. Each coroutine runs its own full network and owns its own root KV
and continuation tree. Policy outputs come from the policy source, while root
WDL and continuation values come from the value source. Terminal values remain
rule-derived. Every continuation wave verifies matching board paths and legal
alignment. Both coroutines must return identical search results. This duplicates
CPU tree bookkeeping but preserves the algorithm and tree budget. Neural row
counts and executor-wave counts are stored separately by checkpoint. Root
executors can split a wave into multiple forwards according to the token budget.
Same-source arms use the ordinary runtime, following exact CUDA equivalence
checks against composition with two separately loaded identical networks.

The four arms are 00 (baseline policy/value), 10 (actor policy/baseline value),
01 (baseline policy/actor value), and 11 (actor policy/value). All face 00.
`mixed/contrasts.json` resamples the same complete opening-pair indices across
all four arms. Report these as protocol-specific effects against the fixed
opponent, not additive Elo contributions. Missing games never become draws.

Position comparisons reuse the exact 100 cached Stockfish positions from ten
held-out monitor continuations generated by actor 54. They are not a random or
representative sample of chess positions. Full histories, FENs and legal moves
are checked before recomputing both policies. Primary measurements are unweighted
actor-minus-baseline expectation and greedy-move expectation changes, with game
cluster bootstrap intervals. CP measurements require finite CP scores for every
legal move. Raw mate scores remain in the copied audit records.

Historical transfer is blocked in this campaign: read-only SSH was refused,
and no local replay from the detached-value training run was found. The transfer
command verifies the saved learner-state weights against actor 54, records
positive exposure counts and run provenance, and emits the missing evidence.
It does not manufacture a transfer estimate. The current transfer command is an
evidence gate, not an implemented historical scoring pipeline; recovered replay
would require adding that pipeline before reporting transfer. The provenance
predicate rejects wrong-run, unconsumed, monitor and actor54-generated substitute
targets.

CPU tests are in `tests/test_policy_regression_audit.py` and the existing search
audit/runtime suites. `python -m scripts.verify_policy_regression` runs the real
CUDA same-source equivalence and mixed-source budget checks for both colors.
