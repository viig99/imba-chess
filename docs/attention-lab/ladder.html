Reduce history first. Compress what remains.

GQA is the first K/V-compression experiment I would try. A short-history comparison comes before it. MLA, learned retrieval and global cache sharing become useful only if their extra machinery addresses a measured cost.

This is a proposed experiment ladder, not an account of DeepSeek's release chronology or a promise that every higher rung is better. Each change after compilation needs training or adaptation and strength evaluation.

1 · Test a short temporal windowReduce the number of historical board positions read by each query

Compare full history against windows of 8, 16 and 32 positions. These are suggested experimental sizes, not validated defaults. A window of 16 positions is approximately eight full moves. Keep the separate 64-square encoder fully connected in these experiments: temporal locality is different from locality on the board.

Sliding-window attention costs roughly O(TW) attention work during training and O(W) per cached query, instead of O(T²) and O(T). To obtain bounded inference cache storage, the decoder must actually evict or avoid retaining inaccessible entries. Kernel tiles and other model work limit practical speedups.

A window is not a hard history reset. Eight layers, each seeing eight positions including the current one, have a theoretical temporal receptive field of 1 + 8 × 7 = 57 positions. Re-encoding only the last eight raw positions is a different experiment.

Current-position-only is a useful diagnostic, but one-key softmax equals one: temporal Q/K cannot affect the mixture. That is not a capacity-matched replacement model. Keep exact repetition/draw-rule state in the engine, and distinguish it from the board features supplied to the network.

2 · Try grouped-query attention: 16 → 8 → 4 KV headsKeep 16 query heads; share stored keys and values
MHA: Q0 → K0,V0    Q1 → K1,V1    Q2 → K2,V2    Q3 → K3,V3
GQA: Q0 ─┐         Q2 ─┐
         ├→ K0,V0      ├→ K1,V1
     Q1 ─┘         Q3 ─┘

Queries in a group still compute different attention weights. They share the representation they read. In HSTU, retain the query-head count, per-query-head relative bias, U gate and output width; reduce the K/V projections and update all cache readers/writers.

For v4's 8 layers, 16 heads and 64-wide K/V, FP32 temporal KV costs 64 KiB per position across the stack. Four KV heads reduce that component to 16 KiB. QK/AV still operate for 16 query heads, so a 4× smaller cache does not imply 4× faster training or search. The kernel must support grouped K/V without storing expanded copies.

GQA paper. The 12-query-head lineage would use divisible group counts such as 6 or 3 instead.

3 · If old history helps, use occasional global layersLocal layers cheaply refine; selected layers retrieve distant context
Eight-layer example:  local → local → global → local → local → global → local → global

This is an experimental schedule, not the DeepSeek-V4.1 schedule. All eight layers still execute. Local layers can retain W entries; global layers retain T. With equal KV widths, the raw cache scales as (5W + 3T) instead of 8T.

At T=256 and W=16, that is 848 versus 2048 layer-position entries: about 2.4× less raw KV. Global information can flow into later local layers. If local-only already preserves quality, adding global access has no established benefit.

Three different ideas are often called “layer sparsity”: restrict each layer's attention edges; reuse another layer's KV; or skip entire layers. They change different computations. Start with fixed local/global patterns before learned layer skipping.

4 · Experiment with limited cross-layer KV sharingFewer cache owners; every layer still has its own query and update

As a separate experiment, layer 2 could read layer 1's KV, layer 4 read layer 3's, and so on. An all-shared-pairs design has four cache owners across eight layers. It needs training: upper-layer queries must learn to interpret the owner's representation, and gradients must flow correctly to shared KV producers.

Sharing weights alone does not share caches: the same projection applied to different layer inputs gives different KV. Sharing KV also does not mean copying attention outputs. Cross-Layer Attention paper.

5 · MLA: learn a compact memory for each positionMore flexible compression, with a more involved decoder
GQA: store fewer explicit K/V heads
MLA: store c = Wdown x; derive head-specific K = WK c and V = WV c

Efficient MLA can move linear projections through attention algebra so decoding does not reconstruct the full historical KV on every query. DeepSeek-V2 also uses a separate positional component. DeepSeek-V2 §2.1.

Our HSTU has SiLU on K/V projections and normalization plus a U gate after attention. Linear absorption cannot simply pass through these operations. A chess MLA variant needs a deliberate parameterization and cache/kernel design. Our additive relative bias avoids the exact RoPE issue in V2, but does not remove the nonlinearities.

Try this only if GQA leaves KV memory or bandwidth as a meaningful bottleneck. A smaller cache can still take longer to read and process with the wrong reconstruction strategy.

6 · Compress old positions, then consider sparse retrievalLocal exact entries + a small older memory

A simpler prototype than a learned indexer is a short local window plus a few causally constructed summaries of older positions. Test whether any older memory improves the short-window model before adding top-k selection.

For chess, merging several boards can blur exact tactical or repetition information. The current board already encodes piece locations, so the benefit of a summary of old boards is uncertain. A fixed BOS token cannot summarize later moves in a causal model.

Learned retrieval adds indexer scoring, selection and gathers. At roughly 512 positions, copying a Top-512 policy produces effectively dense retrieval. LLM gains at extremely long contexts do not predict gains here.

7 · CSA2-style sharing of global memory and selectionsCombine independently tested mechanisms only when justified

In the supplied V4.1 report, Full creates global KV and selects entries; Reindex reuses global KV but selects again; Reuse reuses both KV and selected indices. Every mode computes fresh main queries and local sliding-window KV. Reusing indices alone does not reduce main KV storage.

That is more involved than simply running global attention every third layer. The report also combines temporal compression, a causal encoder–decoder and hierarchical indexing. These target long-context storage and retrieval costs which may be absent in a chess model.

“Global prefix” has several meanings

MeaningWhat it does in chess
Share an identical game prefix across search branchesExact storage reuse when model inputs and weights match. Our search already shares prefix storage; this does not compress its representation.
Allow every query to read a fixed prefixA mask choice. The opening prefix is not a learned summary of subsequent play.
Keep summaries of old context globally visibleA model change. Summaries must be constructed causally and their chess value must be demonstrated.
Share global KV across neural layersA model/cache ownership change, such as the CSA2 mechanism above.

The experiment I would run next

After the execution benchmark: compare full history with W=16 and W=32 under matched training budgets. Separately compare 16 versus 8 KV heads with the original history policy. Combine only changes that pass independently; consider four KV heads next. Current-only is an additional diagnostic, not a demand to redesign the HSTU block.

Judge correctness and strength at equal search budgets, then throughput and strength at equal wall-clock budgets. Check tactical positions, repetition/draw handling, calibration and transpositions reached through different histories. Architecture changes need learning; truncating an existing checkpoint only at inference is a distribution shift.
